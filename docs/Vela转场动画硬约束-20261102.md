# Vela 手环上的转场动画硬约束（2026-11-02 实证）

> 结论先行：**这个平台上「整页几何变换（transform）做页面转场」不可用；能做的是「纯色无文字节点的 opacity 动画」，且该节点绝不能是 flex 容器的子元素。**

## 一、四组实证对照

| 版本 | 做法 | 结果 |
|---|---|---|
| 0.0.104 | 无动画，纯 `router.push` | ✅ 真机正常 |
| 0.0.105 | `.page` 内两个 `position:absolute` 层（推挤双层） | ❌ 模拟器启动即退 |
| 0.0.108 | `.page` 挂 `@keyframes` + `translateX(0 → -100%)` | ❌ **真机黑屏重启（设备级，非应用闪退）** |
| 0.0.110 | `.page` 内加 `position:absolute` 的 opacity 遮罩 | ❌ 模拟器上点按钮后应用直接退出、全屏黑 |
| 0.0.111 | `.root` 纯定位容器 + 遮罩作 `.page` **兄弟** | ✅ 模拟器启动/进入/返回/二次进入全通过（待真机验） |

## 二、根因：两条不同的死法，两个不同的原因

### 1. 整页 transform → 设备级重启（0.0.108）

`translateX(-100%)` 作用在整页容器上，系统会把整屏当成一张纹理重新合成。手环显存/渲染线程扛不住，watchdog 超时后**重启整机**。

注意区分：应用闪退只会退回表盘，**黑屏重启是系统级故障**。这个代价比闪退严重得多，不要拿真机去试探。

### 2. flex 容器里混 absolute 子元素 → 整页黑屏（0.0.105 / 0.0.110）

这条约束早就在 `ev/class-schedule/src/pages/watch-face-animated/watch-face-animated.ux` 头注释第④条写死了：

> `.page` 只给 width/height:100% + position:relative，子元素全 absolute 手写坐标，**不叠 flex 居中（与 absolute 共存会黑屏）**

倒数日的首页 `.page` 是 `flex-direction: column; align-items: center` 布局，往里面塞 absolute 遮罩就中了这条。0.0.105 的双层方案也是同一个死因——当时误判成 transform 的问题，实际是布局结构问题。

### 3. opacity 动画本身是安全的

`watch-face-animated.ux` 有唯一一条被验证可用的 `@keyframes`：

```css
/* 全页唯一动画：只动 opacity，纯色无文字节点 → 允许 */
@keyframes kf-breathe {
  0%   { opacity: 0.35; }
  50%  { opacity: 1; }
  100% { opacity: 0.35; }
}
```

约束是三条：**只改 opacity（或字面量 transform）、节点是纯色 div、节点无文字**。

## 三、可用的正确写法（0.0.111 采用）

结构上把遮罩从 flex 容器里摘出来，做兄弟节点：

```html
<template>
  <div class="root">          <!-- 只 position:relative + 尺寸，不放 flex -->
    <div class="page">        <!-- 原 flex 布局，内容照旧 -->
      ...
    </div>
    <div class="dim" if="{{ dim }}"></div>   <!-- 遮罩：.page 的兄弟 -->
  </div>
</template>
```

```css
.root { width: 100%; height: 100%; position: relative; }

@keyframes fadeIn {
  from { opacity: 0; }
  to   { opacity: 1; }
}

.dim {
  position: absolute;
  left: 0; top: 0;
  width: 100%; height: 100%;
  background-color: #000000;
  animation-name: fadeIn;
  animation-duration: 260ms;
  animation-timing-function: ease-in;
  animation-fill-mode: forwards;
}
```

要点：
- 遮罩用 `if` 控制存在性，**平时不在 DOM 里**，所以不会拦截点击（这是 `.h4` 那类透明盖踩坑的规避方式）。
- 动画 260ms，但 `router.push` 放在 200ms —— 故意让动画没播完就切页。这样即使设备不支持 `animation-fill-mode`（动画结束会弹回 `opacity:0`）也看不出来。
- `onShow` 里必须清 `dim = false`，否则从子页返回时整屏黑、点击全被遮罩挡住。

## 四、可选的动画形态排序（从安全到危险）

1. **纯色节点 opacity 渐变**（0.0.111）— 可用
2. 小尺寸纯色节点的 `scale` / `rotate`（loading-lab 实证）— 可用
3. 小范围 `translateX`（几十像素级）— 未验证，理论可试
4. 整页 `translateX` — ❌ 设备重启
5. 整页 `transform` + 多层叠加 — ❌ 黑屏

## 五、为什么最终没做成「推挤」

用户要的效果是：当前页被推到一边、后一页从侧面同时进来。这要求两页**在同一次合成里各自位移**，本质上就是第 4、5 类。已知这类操作会让设备重启，所以退到第 1 类（淡出），视觉上是「页面渐暗 → 新页出现」，不是推挤。

要真做推挤，只能放弃 `router` 转场、在**同一个页面内**做横排双屏容器平移——但那同样是整页 transform，风险不降反升，且科目页含键盘组件，塞进同一页风险更大。**结论：在 Vela 手环上不做推挤。**
