# 诊断

> 排障专用页：把设备、系统、词库与自检结果集中展示，供用户截图发给开发者。
> 实现：`src/pages/diag/diag.ux`（225 行）

## 1. 页面职责

| 职责 | 说明 |
|---|---|
| 采集 | `readDevice()` 读机型/屏幕/系统，`readDict()` 读输入法词库状态 |
| 渲染 | `renderRows()` 生成「标签 + 值」行 |
| 自检 | 「测试结果」区展示内置检查项结论 |
| 运维 | 「刷新」重新采集，「清空」清掉诊断日志 |

这是唯一一个**内容行数随设备与日志变化的页面**，页面高度不固定。

## 2. 路由与入口

| 项 | 值 |
|---|---|
| 路由 | `pages/diag` |
| 文件 | `src/pages/diag/diag.ux` |
| 入参 | 无 |
| 上游 | 设置页「诊断」 |
| 下游 | 返回设置页 |

## 3. 页面结构

```
scroll (scroll-y)   ← 行数不定，必须可滚
├── 页头         「诊断信息」+ 副标题「截图发给开发者」
├── 设备区       版本 / 机型 / 屏幕 / 系统
├── 词库区       词库状态
├── 自检区       测试结果
└── 操作区       刷新 / 清空
```

## 4. 数据与存储

| key | 类型 | 说明 |
|---|---|---|
| `diag` | string \| Array | 诊断日志，`clearLog()` 清空；仅本地，不上报 |

设备信息来自系统接口，不落库，每次 `onInit` / `onShow` 现取。

## 5. 交互规则

| 手势 | 位置 | 行为 |
|---|---|---|
| 点击 | 刷新 | `refresh()` → 重新 `readDevice()` + `readDict()` + `renderRows()` |
| 点击 | 清空 | `clearLog()` → 清诊断日志并重渲染 |
| 滑动 | 内容区 | 上下滚动查看全部诊断行 |
| 点击 | 返回 | 回设置页 |

## 6. 状态与边界

| 状态 | 表现 |
|---|---|
| 系统接口取不到值 | 该项显示占位（如「未知」），不整页报错 |
| 日志为空 | 「清空」仍可点，无副作用 |
| 诊断行超一屏 | 靠 `scroll-y` 滚动查看，不截断 |
| 用户要反馈问题 | 界面直接提示「截图发给开发者」，本页设计目标就是被截图 |

## 7. 平台约束（Vela 手环）

1. **必须有 scroll**：诊断行数随设备信息与日志增长，单屏装不下。
2. 字号取 `ev-six` 档位中偏小的一档（24），一屏能容纳更多行。
3. 只读展示，本页不提供任何修改系统的能力。
4. 不上报、不联网 —— 隐私边界明确写死在这里。

## 8. 验收要点

- [ ] 进入即显示版本、机型、屏幕、系统四项，值非空
- [ ] 词库状态与设置里的输入法实际可用性一致
- [ ] 点刷新后内容重新采集，不出现空白区
- [ ] 点清空后日志区为空，其他诊断项不受影响
- [ ] 内容超一屏时可滚到底，最后一行完整可见
