# 设置页

> 全应用的中转站：主题、昵称、诊断三个子页入口，加上清空数据与退出应用两个危险动作。
> 实现：`src/pages/settings/settings.ux`（236 行）

## 1. 页面职责

| 职责 | 说明 |
|---|---|
| 跳转 | 主题 / 昵称 / 诊断三个子页 |
| 展示 | 当前主题名、当前昵称（未设置时显示「未设置」） |
| 危险动作 | 清空全部数据（二次确认）、退出应用 |

本页是**单屏页**：内容固定为 5 行菜单，一屏装得下，不需要滚动。

## 2. 路由与入口

| 项 | 值 |
|---|---|
| 路由 | `pages/settings` |
| 文件 | `src/pages/settings/settings.ux` |
| 入参 | 无 |
| 上游 | `cd-list` 右上角「设置」 |
| 下游 | `/pages/theme`、`/pages/nickname`、`/pages/diag` |

## 3. 页面结构

```
div.page（单屏，无 scroll）
├── 页头胶囊  后退 + 「设置」
└── 菜单区
    ├── 主题   → goTheme()    右侧显示当前主题名
    ├── 昵称   → goNick()     右侧显示 cd_nick，空则「未设置」
    ├── 诊断   → goDiag()     右侧显示「打开」
    ├── 清空   → clearAll()   二次确认
    └── 退出   → quitApp()    关闭当前应用
```

## 4. 数据与存储

| key | 类型 | 说明 |
|---|---|---|
| `cd_nick` | string | 昵称，本页只读；为空时右侧渲染「未设置」 |
| `cd_clear_arm` | flag | 「清空已武装」标记，用于二次确认计时；确认窗口过期自动失效 |
| 主题 key | string | 由 `loadTheme()` 读取，用于右侧文案 |

`onShow` 每次进入都重新 `loadAll()`，因此从昵称页返回时右侧文案立即刷新，不依赖回调。

## 5. 交互规则

| 手势 | 位置 | 行为 |
|---|---|---|
| 点击 | 主题 | `goTheme()` → `/pages/theme` |
| 点击 | 昵称 | `goNick()` → `/pages/nickname` |
| 点击 | 诊断 | `goDiag()` → `/pages/diag` |
| 点击 | 清空 | `clearAll()`：首次只武装（写 `cd_clear_arm`），窗口内再次点击才真删 |
| 点击 | 退出 | `quitApp()` → 关闭应用，回到桌面 |
| 点击 | 返回 | `goBack()` → 回 `cd-list` |

## 6. 状态与边界

| 状态 | 表现 |
|---|---|
| 昵称为空 | 右侧显示灰色「未设置」，不显示空字符串 |
| 清空只点一次 | 数据不动，返回或超时后武装状态自动失效 |
| 清空连点两次 | 列表、昵称、主题偏好全部清除，回到初始状态 |
| 无数据可清 | 仍执行，不报错 |

**为什么清空要两次**：本页是唯一能一次抹掉全部倒数日的入口，误触代价不可逆，且手环上没有撤销。

## 7. 平台约束（Vela 手环）

1. 单屏页：5 行菜单不滚动。**不要为了凑长图往这里堆功能** —— 页面该多长就多长。
2. 页头胶囊与 `theme` / `nickname` / `cd-list` 同构。
3. `quitApp()` 走系统 `app.terminate`，手环无任务管理器，这是唯一的正常退出路径。
4. 危险项（清空、退出）排在下半区，与常规跳转项拉开距离。

## 8. 验收要点

- [ ] 三个子页都能进入并正确返回
- [ ] 昵称设置后返回本页，右侧立刻显示新昵称
- [ ] 未设昵称时显示「未设置」
- [ ] 清空点击一次数据仍在；连点两次数据清空
- [ ] 退出后回到桌面，重新进入应用数据完好
- [ ] 切换主题后返回本页，整页配色同步
