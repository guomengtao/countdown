# 倒数日 图标（logo）规范与本次改版

日期：2026-11-01
产物：`src/logo.png`，128×128 RGBA，6518 字节

## 一、官方到底有没有规定尺寸

查证结论：**Vela 官方文档没有硬性规定图标像素尺寸**。

- 官方《项目概览》只规定路径：图标放在 `src/common/images/logo.png`，由 `manifest.json` 的 `icon` 字段引用。
- 官方《概述》《多屏适配》两章未出现图标尺寸要求。
- 业界快应用通用口径是 192×192（华为/vivo 快应用配置文档明确写「提供 192x192 大小的即可」），Vela 未跟进这条规定。

本项目沿用 **128×128**，理由：

| 理由 | 说明 |
|---|---|
| 与自家课程表一致 | `ev/class-schedule/src/logo.png` 就是 128×128 |
| 显示尺寸足够 | 手环应用列表图标实际渲染约 56~60px，128 相当于 2 倍图以上 |
| 体积更小 | 128 约 6.5KB，192 约 14KB，手环包体寸土寸金 |

所以「比别人的大一圈」不是文件像素的问题 —— **128 和 192 在列表里显示的物理大小完全一样**，系统会按容器缩放。

## 二、真正的原因：画面撑满画布

旧图标（与课程表同一张图）的问题：

- 主体图形外圈有一道细虚线环，半径几乎顶到画布边缘，y=2 处就已经有像素
- 四周没有任何透明安全边
- 系统把图片缩放到图标容器时，整幅画面顶满容器 → 视觉上比别家（四周留 10% 透明边）大一圈，且在圆形裁切下虚线环被削掉，看着「缺一块」

## 三、新图标设计

```
画布 128×128 透明底
  └ 主体圆 r=50，直径 100 → 四周各留 14px 透明边（11%）
      ├ 渐变底 #2F6BFF → #10349E（上浅下深，竖向）
      ├ 底环 r=40 白色 18% 透明度 stroke 7（轨道）
      ├ 进度弧 r=40 黄色 #FFD60A stroke 7，71.8%，起点 135° 顺时针
      └ 中心数字「7」白色 Helvetica Neue Bold 52px（倒数天数）
```

设计口径：

- **黄色弧 + 数字 7** 表达「天数在减少」，与课程表的「课表行」图形不撞车
- 数字取 7 是常见倒数周数，字形张口小、小尺寸不易糊
- 只用 3 个色块层级，60px 下仍可辨认
- 圆环轨道用 18% 白而非实色，避免小尺寸下和进度弧混成一圈

## 四、重新生成方式

```bash
cd ev/countdown
cat > /tmp/logo-countdown.svg <<'EOF'
<svg xmlns="http://www.w3.org/2000/svg" width="128" height="128" viewBox="0 0 128 128">
  <defs>
    <linearGradient id="bg" x1="0" y1="0" x2="0" y2="1">
      <stop offset="0" stop-color="#2F6BFF"/>
      <stop offset="1" stop-color="#10349E"/>
    </linearGradient>
  </defs>
  <circle cx="64" cy="64" r="50" fill="url(#bg)"/>
  <circle cx="64" cy="64" r="40" fill="none" stroke="#FFFFFF" stroke-opacity="0.18" stroke-width="7"/>
  <circle cx="64" cy="64" r="40" fill="none" stroke="#FFD60A" stroke-width="7"
          stroke-linecap="round" stroke-dasharray="181 252"
          transform="rotate(135 64 64)"/>
  <text x="64" y="82" text-anchor="middle" font-family="Helvetica Neue, Helvetica, Arial"
        font-size="52" font-weight="bold" fill="#FFFFFF">7</text>
</svg>
EOF
rsvg-convert -w 128 -h 128 -o src/logo.png /tmp/logo-countdown.svg
```

（`rsvg-convert` 由 `brew install librsvg` 提供，本机已有。）

## 五、以后新增应用的图标口径

1. 画布 128×128，PNG RGBA，透明底
2. **主体图形外接圆直径不超过 100px**，四周留 ≥12px 透明边
3. 主体不超过 3 个色层，最小可读尺寸按 56px 校验（可以 `PIL` 缩到 56 看一眼再定稿）
4. 不要用整圈虚线/描边贴边，圆形裁切会削掉
5. 生成源 SVG 一并留档，改色改数字只需改两行

## 七、v0.0.88 改版：换成课程表图形缩小版

### 为什么废弃「圆环 + 数字 7」

上一版用「黄弧进度环 + 中心数字 7」表达倒数日，问题在于：**数字 7 是我随手取的天数示例，没有可解释的语义**。图标是静态的，7 既不表示某个真实倒数的剩余天数，也读不出「倒数」这个动作——它只是「一个数字」。用户提问即暴露了这一点：看图的人会问「7 是什么意思」，说明它没自解释。此外圆环+数字与课程表的图形语言不统一，两个应用并排看不出是一家的。

### 现行方案：家族一致 + 缩到统一视觉尺寸

直接把课程表 logo 的图形缩到主体直径 100，四周留 14px（11%）透明边，画布仍是 128×128：

```python
from PIL import Image
src = Image.open("../class-schedule/src/logo.png").convert("RGBA")
inner, W = 100, 128
small = src.resize((inner, inner), Image.LANCZOS)
canvas = Image.new("RGBA", (W, W), (0, 0, 0, 0))
canvas.paste(small, ((W-inner)//2, (W-inner)//2), small)
canvas.save("src/logo.png")
```

校验：`alpha bbox` 应为 `(14, 14, 114, 114)`，顶边 `(64,0)` 全透明。

要点：

- 课程表原图主体撑满 128（`alpha bbox = (0,0,128,128)`），同一图形在两个包里显示大小不一致，这是「我们大一圈」的观感来源
- 缩放只能整图等比缩，**不要**先裁再缩，否则课表图形会变形
- 缩到 100 后在 60px 下细节会略糊（左侧小方块行变密），但轮廓仍可辨，可接受
- 好处：与课程表共用一套图形语言，列表里两个应用一眼是一家的

## 八、v0.0.90 定稿：日历 + 数字 7（语境化数字）

第七节的「课程表缩小版」只在尺寸上解决了问题，图形辨识度不够：虚线外环 + 密集课表行缩到 60px 后糊成一团。三个方案 60px 实测对比后定稿为「日历 + 数字」：

| 方案 | 60px 可辨性 | 问题 |
|---|---|---|
| 课程表缩小 | 差 | 轮廓散掉，看不清是什么 |
| 日历 + 进度条 | 中 | 黄色进度条没有「量」的含义，只是装饰 |
| **日历 + 数字 7** | **优** | 无 |

### 为什么这次「7」成立，上一版不成立

同一个数字，位置决定语义：

- 上一版：数字孤立在圆心，周围是抽象进度环 → 读者只能问「7 是什么」
- 本版：数字落在日历格内，上方有挂环、下方有日期点、整体是日历形 → 读者自动读成「7 号」

**结论：图标里的数字必须有依附的实体，否则不成立。** 这条比「用什么数字」重要得多。

### 绘制要点

- 画布 128，主体圆 r=50，四周自动留 14px（11%）透明边
- 配色沿用课程表色系：底 `#1B4F8F → #0B1E43` 渐变，日历体 `#7DC6E2`，表头/数字 `#10306B`，黄点缀 `#FFD60A`
- 挂环 6×14 圆角 3，位于 x=44 / x=78，顶端 y=30
- 日历体 60×54 圆角 9，起点 (34,38)；表头高 16
- 数字 7：Helvetica Neue Bold 30px，基线 y=84，居中
- 右下黄点 r=3 在 (88,84)——表示「这天被标记」，是倒数日的视觉线索

源 SVG 存于 `docs/logo-countdown.svg`，改数字只需改 `<text>` 一行后重新 `rsvg-convert -w 128 -h 128`。

## 九、v0.0.92 修正：不要留透明边，直接输出内容尺寸

### 真机发现的错误假设

真机 11 装上 v0.0.90 后反馈：**图标压住了下方的应用名称**。

这说明 Vela 的应用列表**按图片的实际像素尺寸占位渲染，不是把图片等比缩放进一个固定容器**。据此，之前「留 11% 透明安全边会让图标看起来小一圈」的推断是错的：

- 128 画布 + 100 内容 = **占位仍是 128**，只是内容缩在里面显得空，遮挡问题一点没解决
- 系统要的是「图片本身就是图标」，不是「图片里画了一个图标」

上一节第七、八节里「四周留 11% 透明边」的做法因此作废，仅作为「为什么当时那样想」的记录保留。

### 现行口径

```python
from PIL import Image
im = Image.open("src/logo.png").convert("RGBA")
im.crop(im.getbbox()).save("src/logo.png")   # 裁掉全部透明留白
```

- 输出 100×100，内容满幅，`alpha bbox = (0,0,100,100)`
- 圆形图标四角（圆外区域）仍然是透明，这是形状决定的，不可避免
- 占位从 128 降到 100，减少 22%

### 通用规则（新应用直接照做）

1. 图标内容**顶满画布**，不要人为留安全边——留边只会在固定容器里让图标显小，在按像素占位的系统里则是白占地方
2. 画布尺寸按目标显示尺寸给，手环列表约 60px 渲染，给 100 已到 1.7 倍图
3. 若仍遮挡文字，继续下调画布到 88 / 80，**不要**改内容占比
4. 判断依据：真机上图标是否压名称，而不是本地缩放预览
