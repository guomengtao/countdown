## 一、为什么选这个页面

- `ev/countdown` 是独立仓（`guomengtao/countdown.git`），包名 `com.application.watch.countdown`，本次试点前**完全没有 i18n 目录**，从零接最干净。
- 设置页只有 236 行、10 条静态文案，且是**最狠的版式场景**：`.list` 宽 168px，`.item` 左右 padding 14/12 ⇒ 内容宽仅 **142px**；`.it-k` / `.it-v` 同为 **24px 且 `lines: 1`**，多数条目是 key + value 双列同行。这里能放下，其它页面基本都能放。
- 列表 7 项 × 54 = 378 + 页头 72 + 版号 30 = 480 < 490，**没有任何可加项的空间**。

## 八、本轮实测踩坑（真实发生，别再踩）

1. **Vela 构建链要求声明 `system.configuration`，与快应用联盟文档冲突**：`app.ux` 里 `require('@system.configuration')` 后，`aiot release --enable-jsc` 直接报 `missing feature: [{"name":"system.configuration"}]` 并中止构建，而官方文档《应用配置 configuration》写的是「接口声明 **无需声明**」。修法：在 `src/manifest.json` 的 `features` 补一项即可（官方给的另一条路 `aiot --complete-feature` 会自动补全，但会引入不透明的全量 feature）。**结论：凡在代码里 require 任何 `@system.*`，Vela 工程一律先在 manifest 声明，别信联盟文档的「无需声明」。** 声明不等于提高平台版本，`minPlatformVersion` 仍保持 1050；运行时用 `try/catch` 兜底。
2. **校验脚本第一版误判**：曾把「单条译文比中文原文宽」设为硬失败，结果 4 条 2 汉字 → 4~5 字母的词（`Theme` / `Name` / `Diag` / `Exit`）被判 FAIL，但 7 行行级合计全部达标。根因是把「双列同行」当成两个独立行算，违背 §3.21 第 9.4 条「两列之间可互相借额度」。已修：单条超宽降为提示，硬判据只看行级合计。
