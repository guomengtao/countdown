## 二、README 里有一条我们此前理解错的条款

官方对 `screentype` 的定义原文：

| 值 | 官方描述 |
|---|---|
| `rect` | 方形屏布局，**对应 designWidth ≥ 336** |
| `circle` | 圆形屏布局，对应 designWidth 为 480 |
| `pill-shaped` | 胶囊形屏布局，**对应 designWidth ≥ 192** |

我们两个项目的 `manifest.config.designWidth` 都是 `"device-width"`，手环 11 实际为 **212**。

按官方定义，**212 应该走 `pill-shaped`，而 `rect` 本来是给 336 以上的设备用的**。

这解释了你之前的疑问「明明是胶囊屏，为什么矩形能开」——不是矩形"更适合"手环 11，而是：

- `rect` 分支用 `scroll-x` 横向滚动 + 百分比容器，键宽固定 60px，排不下就滚动。**它对画布宽度不敏感，所以在 212 上"能开但只能看到 3 个键"**。
- `pill-shaped` 是官方为 192 设计的分支，理论上最贴 212，但它大量用 `position:absolute` + `(screenWidth-192)/2` 计算留白，对容器高度和初始化时序敏感。

**注意 `screenWidth` 的初值是 336**（源码注释：针对 rect 设备自动获取）。`adjustScreenWidth()` 在 `screentype` 为 `rect` 或 `pill-shaped` 时都会调用，但 `device.getInfo` 是异步——**第一帧一定用 336 渲染**。pill 分支拿 336 算 `(336-192)/2 = 72px` 双边留白，192 内容 + 144 留白 = 336，塞进 212 的屏，第一帧就溢出。

## 三、更关键：官方有一个未修复的崩溃 issue，症状与我们完全吻合

**Issue #14（2026-07-14 至今 open，0 评论，无修复）：**
> 重装应用后第二次打开带键盘的页面必崩（Data Abort at DFAR=0x11/0x12）

原文要点：
- 首次启动进带键盘页 → 正常
- 返回 → 再次进入同一页面 → **崩溃**
- 日志：`arm_dataabort PC:0080e508 DFAR:00000011`
- 根因：`$watch` 绑定的 bound 函数（`watchMaxLengthPropsChange`）在 destroy 时 REFS=1 泄漏，`JsSubComponentFactory` 的静态 prop 缓存存活到下一轮，第二轮拿野指针解引用

源码里对得上：`InputMethod.ux:454` 就是 `this.$watch("hide", "watchHidePropsChange")`，同一模式。

**如果这条成立，我们之前"七种形态只有一种能开"的解读就要改：**
不是"6 种布局崩"，而是**第一次进入键盘页成功，之后每次再进都崩**——与屏型无关。用户看到的现象（一个能开、其他全崩）刚好符合这个特征。

这条也解释了为什么模拟器抓不到：我们每次 `vela up` 都是全新安装、只测"第一次"。

## 四、结论：不改官方组件这个决定，是对的

理由不是"改动有风险"，而是**改了也修不好**：

1. 布局层面：pill 分支的问题在异步时序 + 绝对定位，改动面覆盖整个分支，等于重写
2. 崩溃层面：issue #14 是 C++ 侧静态缓存野指针，**改 .ux 只能绕，不能修**
3. 维护层面：官方一个半月没更新，我们 fork 之后要永久背差异

**所以路线固定为：不做 pill-lite、不改组件源码，只用官方原样 + 传参解决。**

## 五、下一步：一个只需一次点击的决定性验证

当前所有推测都指向两种可能，而它们可以用**一次安装、一次点击**区分开：

| 假设 | 验证方法 | 若成立 |
|---|---|---|
| H-A：pill 分支在 212 上崩溃 | 全新安装后，**第一个**就点"胶囊全键盘" | 崩 → 布局/时序问题，212 确实不能走 pill |
| H-B：组件重入崩溃（issue #14） | 同上，作为第一次打开 | 能开 → 之前"只有矩形能开"是重入 bug，与屏型无关 |

**关键点：必须保证这是安装后第一次进入任何带键盘的页面。**

如果 H-B 成立，那结论会非常有利：**只要用户每次使用前不重复进出，第一个键盘页是可用的**——但这不是可接受的最终状态，因为倒数日要反复改昵称。后续得靠"应用内只保留一个键盘页、且不做 destroy 重建"这类结构约束来规避。

## 六、核查中顺手确认的三条工程事实

1. 组件默认 `dictionarypath` 就是 `/components/InputMethod/assets/dictionary/`，我们传的值与默认相同，不传也可
2. `maxlength` 官方定义是**候选词展示数量**（README：默认展示的拼音候选词数量），不是输入长度上限——此前标注为"限三字"是错误的
3. 日语支持 `circle` / `rect` / `pill-shaped` 三种布局，但**不支持 T9**
